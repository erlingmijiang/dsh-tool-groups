# 工具组（Tool groups）

把「可选能力」从系统提示里请出去：用户把工具、MCP 工具或技能编成**工具组**，已编组的能力默认不暴露给模型，只在 Agent 需要时由元工具按回合加载。常驻工具与未分组工具始终加载。

## 它解决什么

DSH 默认把每个已注册工具的参数 schema 都交给模型，技能清单也会整体写进会话。工具装得越多，每一轮都要为用不到的能力付固定 token。工具组把「装了什么」和「这一轮要什么」分开：

- **常驻**：文件读写、bash/终端、网络检索、工具组元工具、技能加载器；以及**所有没有编组的工具**（含新装插件带进来的工具、新技能、新 MCP 工具）。不会因为装了新插件而突然消失。
- **按需**：编进工具组的工具/技能默认隐藏；模型调用 `load_tool_group` 后本回合可见，**回合结束自动卸载**。

## 使用

1. **设置 → 工具组配置**
   - *管理工具组*：新建工具组（名称 + 描述）、改名、改描述、删除（行内二次确认）。
   - *对现有工具编组*：每个工具/技能一行，**左侧是名称 + 徽标 + 描述**（描述取自工具定义，截断到 320 字符，够辨认用途），**右侧是下拉菜单**：`常驻` + 每个工具组。改完点底部**「确认生效」**才写入配置并重算可见性；「放弃改动」回到服务端状态；底部会显示还有几项改动未生效。
   - 下拉菜单是**单选**：一个工具/技能归一个组；选 `常驻` 即未分组（未分组默认常驻）。常驻工具的下拉是禁用的。元工具 `manage_tool_groups` 仍支持把同一工具放进多个组（任一组加载即可见）。
   - 一次保存用一个批量请求（`setMemberships`）落盘并只刷新一次可见性。
2. 模型侧四个元工具：
   - `list_tool_groups`：返回组名 + 描述 + 成员数（组的清单**不进系统提示**，只能这样拿）。
   - `load_tool_group` / `unload_tool_group`：本回合装卸。
   - `manage_tool_groups`：建组、改名、改描述、加入/移出成员——用户可以用自然语言让 Agent 代劳；**删除只能在设置页做**。
3. 也可以用自然语言："把画图相关工具归到一个叫『数据可视化』的组，描述写成画图表时用"。

## 机制（不改 DSH 核心）

| 目标 | 用的扩展点 |
| --- | --- |
| 隐藏工具 | `agent.ctx.tools.restrict({ deny })`：DSH 要求限制必须落在 agent 作用域（全局 restrict 会直接抛错），插件在 `agent/created` 为每个 agent 装一次，配置变化时按签名幂等重装 |
| 隐藏技能 | 在 agent 作用域注册同名「运行期影子技能」，`modelInvocable/userInvocable` 全关；分层注册表里近层优先，同名技能被顶掉，技能清单随之收缩（模型改为看到「目录变了」的替换清单，不会每步抖动） |
| 回合回落 | `session/event` 的 `turn/end` 为主，`agent/pre-step` 的 turn 变化为后备 |
| 设置页数据 | `ctx.webServer` 上一条同源 JSON 路由 `POST /__dsh-tool-groups/api`（只收 `application/json`、校验 Origin） |
| 持久化 | `<DSH_HOME>/dsh-tool-groups/config.json`（profile 级，重启保留） |

## 名称机制（双名：AI 侧英文名 / 人类侧中文名）

每个组有两个名字：

| 名字 | 面向 | 用在哪 |
| --- | --- | --- |
| **英文名**（kebab-case，如 `skillcraft`、`office-group`） | AI / 程序 | skill 目录条目名、`load_tool_group` / `unload_tool_group` / `list_tool_groups` 参数与返回值、系统提示说明 |
| **中文名**（如「技能工程」） | 人类 | 仅设置页（`state` 数据面）展示；不出现在目录描述、list/load 输出、系统提示 |

- 英文名必须唯一，且不得与真实技能、其它组中文名或本组成员重名（与本组成员重名会顶掉真实技能）；`office` 组因成员里有 `office` 技能，迁移时自动落为 `office-group`。
- 目录条目**不是技能**，不要用 `skill` 调用；描述里列出**全部成员**（技能 + MCP 工具），用户点名某个工具/技能时可直接看出该加载哪个组。
- 加载前直接 `skill(组内技能名)` 会得到 `not available`——必须先 `load_tool_group`。
- 解析顺序：英文名 → 旧 `tg-<英文名>` 别名 → 成员名；中文名作为**未文档化的兼容兜底**静默接受（旧提示词不失效，但 AI 侧文案不宣传）。
- 解析结果回传 `resolvedFrom` / `resolvedVia`（`english` / `slug` / `member` / `name`）；未知名字的报错只列英文名。
- 系统提示常驻一段约 5 行的说明（`ctx.systemPrompt.section`，order 9000）：按需求+成员名单选组、先 load 再调用。

## 已知边界

- **agent 自己那一层注册的工具不可限制**：`tools.restrict` 只作用于「继承来的」工具（全局层 + 祖先作用域层）。若某个插件把工具注册进 agent 自身作用域，本插件无法隐藏它，会在重试时自动把它从 deny 名单剔除（不会报错刷屏）。
- **技能影子在 agent 作用域**，理论上优先于全局层（含项目级 `/.dsh/skills`、用户级 `~/.dsh/skills`）；项目级技能场景本机未实测。
- 加载状态只在当前回合有效，不跨会话记忆；需要时重新加载即可。
- 只隐藏 schema 与技能条目，不改变工具的执行或授权语义；被隐藏的工具在加载前调用会得到未知工具。
- 路由是 loopback 数据面（与 DSH 其他本地插件的做法一致）：不经过 Remote 的 Peer 鉴权，但做了 method / content-type / Origin 三项检查，挡住跨站页面调用。
- 与 `dsh-ops` 的 `ops_discover_tools` 并存互不干扰：那是另一套发现池，本插件只管「哪些工具进系统提示」。

## 实测数据（本机 desktop profile）

- 工具总量 160（含本插件 4 个元工具），常驻 35 个（文件读写/ops_*、bash/pwsh、terminal_*、web_search/web_fetch、skill、4 个元工具）。
- 把 `render_ui` + `validate_dsh_ui` 编进「数据可视化」后，两者 schema 合计 3934 字符/次请求不再发送；`load_tool_group` 后本回合恢复，`unload_tool_group` 或回合结束又消失（调用返回 `unknown tool`）。
- 体积参考：`dsh_browser_*` 48 个工具 47834 字符、`config_*` 9 个 10064 字符、`mnemon_*` 17 个 21560 字符 —— 编进工具组后这些都是净省。

## 三类管理态

| 管理态 | 含义 | 设置页 | 可否编组 |
| --- | --- | --- | --- |
| 已编组 | 属于某个工具组，默认不进提示词，按回合加载 | 工具/技能列表 | 是（下拉选择） |
| 常驻 | 写死白名单：全部 DSH 原生工具 + 全部 `ops_*` | 标记「常驻」，下拉禁用 | 否 |
| 按需注入 | 注册方用 `when` 做步骤级条件放行，默认根本不进提示词 | 独立虚线区域，只读 | 否 |

「按需注入」的判据不是 `executable(name)`：缺省 toolSet 时它会把所有带条件的注册都算成不可执行，`web_search` 这类"有条件但通常放行"的工具会被误判。
插件在 `agent/pre-step` 里按本步向注册表要一次 admission，`definitions(agent)` 有、`admitted` 没有的才算按需注入。实测命中 16 个：
`exit_plan_mode`、`team_task_create/get/list/update`、以及 `ops_copy/diff/edit_file/move/read_docx/read_pdf/read_table/remove/replace/stat/write_file`。

## 二期的默认分组

| 工具组 | 成员 | 数量 |
| --- | --- | --- |
| 浏览器自动化 | 全部 `dsh_browser_*` | 48 |
| 记忆与知识库 | 全部 `mnemon_*` | 17 |
| 配置备份与同步 | 全部 `config_*` | 9 |

小插件工具（图表、侧边栏、IM、需求澄清等）不建组，留在常驻。
